01 · Fundamento

Qué es un servidor MCP

MCP, Model Context Protocol, es un estándar abierto para conectar un modelo de lenguaje con herramientas y datos externos. Un servidor MCP es un programa que expone capacidades —leer una base de datos, consultar una API, editar un diseño— de una forma que cualquier modelo compatible entiende.

El problema que resuelve es de combinatoria. Antes, cada integración se programaba a medida para cada modelo y cada aplicación: n modelos por m herramientas daba n×m integraciones. Con un protocolo común, escribes el servidor una vez y sirve para Claude Code, Claude Desktop o cualquier otro cliente que hable MCP.

La analogía que aguanta

No es un traductor de lenguaje natural a SQL. Es darle manos al modelo: un conjunto de herramientas que tú diseñas, con los límites que tú decides. Y no va solo de leer datos — también de actuar: crear un ticket, abrir un pull request, publicar un diseño.

02 · Piezas

Anatomía de una conexión

Cliente y servidor

El cliente es la aplicación donde tú escribes: Claude Code, Claude Desktop, un IDE. El servidor es el programa que expone las capacidades. La conexión es con estado y bidireccional: no es una serie de peticiones sueltas, es una sesión.

Las tres primitivas

  • Tools — acciones que el modelo invoca. Lo que más se usa.
  • Resources — datos que el modelo lee, como ficheros o registros.
  • Prompts — plantillas de instrucción que dispara el usuario.

Transportes

stdio: el cliente lanza tu servidor como subproceso y hablan por entrada y salida estándar. Sin red, sin puerto, sin URL. Es lo normal para servidores locales. HTTP: el servidor vive en un servicio remoto con su URL y su autenticación, como el de Canva.

El descubrimiento es parte del protocolo

Al conectar, el cliente pregunta «¿qué sabes hacer?» y el servidor responde con la lista de herramientas y sus esquemas JSON. Esto ocurre en tiempo de ejecución, en el handshake. Es una diferencia de fondo con REST, donde la documentación vive fuera del protocolo.

# El handshake, simplificado
→ initialize          cliente se presenta
← serverInfo         servidor responde quién es
→ notifications/initialized
→ tools/list          ¿qué sabes hacer?
← ["listar_plantillas", "validar_contenido", ...]
→ tools/call          ejecuta esta, con estos argumentos
← resultado

03 · Comparación

En qué se parece y en qué no a una API REST

La intuición «es como exponer un servicio por API» es correcta de partida. De hecho muchos servidores MCP no son más que un envoltorio fino sobre una API REST que ya existía. Pero hay diferencias que cambian el diseño.

EjeAPI RESTServidor MCP
ProtocoloVerbos HTTP sobre recursosJSON-RPC 2.0
Transporte típicoRed, siemprestdio local o HTTP remoto
DescubrimientoExterno: OpenAPI, documentaciónDentro del protocolo, en el handshake
ConsumidorCódigo escrito por una personaUn modelo que decide en tiempo real
GranularidadFina y tipo CRUDGruesa y orientada a tarea
La descripción es…Documentación para humanosParte del prompt
La consecuencia práctica

No portes tu REST uno a uno. En vez de GET /users, GET /orders y POST /refunds, expón procesar_devolución_cliente. Cada herramienta ocupa contexto y cada llamada extra es una oportunidad de equivocarse: menos herramientas y más semánticas gana. Y escribe bien las descripciones — una descripción mala rompe la integración aunque el código sea perfecto.

04 · Dinero

Las tres capas de coste

Cuando alguien pregunta «¿cuánto cuesta usar un MCP?», casi siempre está mezclando tres cosas distintas. El protocolo en sí nunca es lo que se paga.

CapaQué esCoste
Protocolo y SDKMCP es un estándar abierto0 €, siempre
Servicio de detrásCanva, Jira, tu base de datosEl de tu plan
Uso del modeloTokens de cada llamadaIncluido en tu suscripción, o por consumo vía API

La regla general: gratis en servicios que ya son gratis (sistema de ficheros, Git, SQLite, ffmpeg) y con el coste del servicio en los de pago. Algunas APIs empresariales exigen un plan concreto para dar acceso, y ahí el MCP ni se conecta. Lo que nunca pasa es que Anthropic cobre un extra por conectar un servidor.

05 · Restricciones

Qué da cada plan de Canva

Canva reparte las capacidades de su MCP por nivel de cuenta. Esto es lo que determina qué se puede automatizar gratis y qué no.

CapacidadPlan mínimo¿Lo necesitamos?
Generar, editar y buscar diseñosTodos, incluido gratuitoSí — es el núcleo
Exportar a imagen o PDFTodosSí
Subir recursos propiosTodosOpcional
Redimensionar a otro formatoProNo — dos plantillas
Autofill de plantillas con camposEnterpriseNo — editamos texto
Brand kits y brand templatesEnterpriseNo
El atajo que evita pagar

Redimensionar de cuadrado a vertical es de Pro. Pero mantener dos plantillas base, una por formato, y editar el texto en cada una, entra en el plan gratuito. Pierdes automatización y ganas cero euros al mes. Los recursos premium siguen saliendo con marca de agua, así que la plantilla debe construirse con elementos gratuitos.

06 · Aplicación

El caso: un post nuevo desde una plantilla

El objetivo: escribir «5 palabras en chino sobre deportes» y obtener un diseño nuevo en Canva, con la plantilla original intacta y sin repetir temas anteriores.

  1. Servidor localElegir plantilla. Se listan las del catálogo y se escoge por descripción, o el usuario la nombra.
  2. Servidor localPedir el contrato. Devuelve los huecos de texto, sus límites de caracteres, las reglas de estilo y los temas ya publicados.
  3. ModeloGenerar el contenido. Las cinco palabras, con carácter, pinyin y traducción, respetando el estilo.
  4. Servidor localValidar. Comprobación determinista: huecos ausentes, textos vacíos, excesos de longitud. Si falla, se corrige y se revalida.
  5. MCP de CanvaDuplicar y editar. Se copia el diseño maestro y se sustituyen los textos en la copia.
  6. Servidor localRegistrar. Se guarda tema, contenido y URL en el historial, que es lo que evita repetirse la próxima vez.
Por qué la validación va en código

Contar caracteres es exactamente el tipo de tarea que un modelo hace regular. El contenido lo genera el modelo, pero los límites duros los comprueba una función. Si el texto no cabe, la plantilla se descuadra visualmente y el post no sirve — así que esa comprobación no puede depender de que el modelo cuente bien.

07 · Diseño

Dos servidores repartiéndose el trabajo

El MCP de Canva sabe de diseños, pero no sabe nada de tus plantillas ni de lo que publicaste el mes pasado. Ese hueco lo llena un segundo servidor, local, escrito por ti. Es un patrón que se repite mucho: el servidor oficial aporta las capacidades, el tuyo aporta el criterio.

Las herramientas del servidor local

HerramientaPara qué
listar_plantillasVer el catálogo y cuántas veces se usó cada una
obtener_plantillaFicha completa: id de Canva, huecos, reglas
planificar_postCuántas slides y desde qué ángulo, por rotación
preparar_encargoEl contrato para un tema, y si ya se usó
validar_contenidoComprobación dura antes de tocar Canva
temas_publicadosHistorial de temas, para no repetirse
elegir_portadaQué plantilla de portada y qué color de título aguanta esa foto
registrar_publicacionGuardar lo hecho, con la URL real
anadir_plantillaRegistrar una plantilla nueva sin editar JSON

Fíjate en que ninguna herramienta se llama ejecutar_sql ni escribir_fichero. Son operaciones concretas y acotadas: eso limita el daño posible y hace que el modelo acierte al elegir.

08 · Honestidad

Lo que esto no hace

  • No publica en Instagram ni TikTok. El MCP de Canva llega hasta exportar a imagen o PDF. Publicar requiere las APIs de Meta y TikTok, que es otro proyecto entero.
  • No corre solo. Un servidor MCP responde cuando tú abres una conversación. No hay nada programado generando posts de madrugada. Para eso harían falta la Connect API y un script propio.
  • No sustituye la revisión. Cambiar un texto puede descuadrar un salto de línea. Se ve a simple vista, pero el modelo no lo ve. Abre el diseño antes de publicar.
  • La edición libre es irregular. Sustituir texto en una plantilla estable funciona bien. «Cámbiame el color de fondo y mueve el logo» ya no.
Regla que no se rompe

Nunca editar el diseño maestro. Siempre duplicar primero y trabajar sobre la copia. Si el cliente no dispone de herramienta de duplicado, se para y se duplica a mano — son cinco segundos, frente a reconstruir una plantilla perdida.
